**Skill** е пакет от инструкции, който учи Claude как да свърши определен вид задача — стъпките за
deploy, checklist за code review, конвенциите на конкретен модул. Вместо да обясняваш едно и също
всеки път, го записваш веднъж като skill.

Ключовото е, че skill-овете се зареждат **при нужда**. В контекста стои само кратко описание;
пълните инструкции влизат едва когато задачата ги изисква. Затова можеш да имаш много скилове, без
да натовариш сесията.

## Как се извикват

  <Column>
    <Card title="Ръчно" icon="mouse-pointer-click">
      Пишеш `/име-на-скила` в промпта — както всяка друга slash команда.
    </Card>
  </Column>
  <Column>
    <Card title="Автоматично" icon="wand-sparkles">
      Claude сам разпознава по `description`, че скилът пасва на задачата, и го зарежда.
    </Card>
  </Column>
</Columns>

Затова `description` е най-важното поле: то е единственото, което Claude вижда, преди да реши дали
да отвори скила.

```text
/create-commit
/deploy-staging
```

Скиловете от plugin се извикват с префикс — името на плъгина, двоеточие, името на скила:

```text
/mattpocock-skills:tdd
```

## Къде живеят

| Място | Обхват | Кога го използваш |
| --- | --- | --- |
| `.claude/skills/<име>/SKILL.md` | Само този проект | Конвенции, команди и процеси, специфични за репото. Комитва се с кода. |
| `~/.claude/skills/<име>/SKILL.md` | Всички твои проекти | Лични навици и работни процеси, които носиш навсякъде. |
| Plugins | Според инсталацията | Готови набори от скилове, инсталирани наведнъж. |
| Marketplace | Според инсталацията | Публични колекции — добавяш marketplace, после инсталираш плъгин от него. |

## Прост SKILL.md

Минималният скил е YAML frontmatter с `name` и `description`, следван от Markdown инструкции:

````markdown SKILL.md
---
name: deploy-staging
description: Deploy-ва текущия branch към staging. Use when the user asks to deploy, ship, or push to staging.
---

# Deploy към staging

## Преди deploy

1. Провери, че тестовете минават: `pnpm test`
2. Провери, че няма uncommitted промени: `git status`

## Deploy

```bash
pnpm build
pnpm exec vercel deploy --prebuilt
```

## След deploy

Провери health endpoint-а и докладвай URL-а на deployment-а.
````

## Допълнителни файлове

Скилът не е само един файл. До `SKILL.md` можеш да сложиш:

- **`references/`** — дълги справочни материали, които Claude чете само когато му потрябват.
- **`scripts/`** — готови скриптове, които скилът извиква, вместо да ги пише наново всеки път.
- **`assets/`** — шаблони, конфигурации, patch файлове.

Идеята е `SKILL.md` да остане кратък и да сочи към останалото: „за пълния списък провери
`references/checklist.md`".

## Skill или субагент?

| | Skill | Субагент |
| --- | --- | --- |
| Какво е | Инструкции за текущата сесия | Отделна сесия със собствен контекст |
| Контекст | Влиза в твоя контекст | Има свой, изолиран контекст |
| Кога | Процедура, която Claude трябва да следва | Голяма задача, чиито междинни стъпки не искаш в основния разговор |
| Управление | Файл в `.claude/skills/` | `/agents` и `.claude/agents/` |

Двете се комбинират: субагент, който зарежда скил, е много честа схема.
